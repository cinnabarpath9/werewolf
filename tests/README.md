# tests/ 里有什么

- `t_*.py`：**行为测试**（真跑引擎 / 真连 WS / 真开浏览器）。
- `check_*.py`：**结构检查**（参数接线、签名、分发是否生效）。
  `check_multiplayer.py` 专测联机：多真人座位、并发提问路由、台账按座位过滤、访客令牌/联机码分离。
- `run_all.py`：一键回归 —— 三档速度，判据写死在代码里的分档清单中（见文件头注释）。
- `cdp_lite.py`：无头浏览器驱动（页面测试用）。`extract_js.py`：把前端内联 JS 抽出来给 `node --check` 验语法。
- `live_token.py`：**配对码的唯一来源**（读项目根 `配对码.txt`，也认环境变量 `WOLF_TOKEN`）。
  要连线上 8077 的测试都从它拿码，**不许把码写死在测试里**（写死 = 凭证进仓库 + 一换码十几个测试一起红）。
- `mutation_verify.py`：**变异验证**（手动工具，不进三档）。把每条修复**改回旧写法**、跑对应脚本、
  确认它**变红**，再按字节还原并核对 sha256 —— 用来证明新加的断言不是"永远为真"。
  ⚠️ 它会**临时改写 `wolf/*.py`**，所以不要和别的测试并行跑；跑法 `python mutation_verify.py`。
- `fake_llm.py` / `test-config.yaml` / `stall-config.yaml`：夹具与测试配置。
- `_logs/`：**运行日志统一丢这里**（以前几百个 .log 直接堆在目录里）。
- `legacy/`：历史遗留 —— 一次性补丁/诊断脚本、以及上一轮的 `_verify_c` harness。**不要在这里加新测试**；它们只是留证。

约定：断言行为就用真实路径（引擎/浏览器），断言结构只查"机关在不在"，别盯字面写法（重构一次就假红）；每个脚本最后打印 `共 N 项：通过 X，失败 Y`。

## 三档怎么跑

```powershell
python run_all.py            # 全量：盘上每个脚本都跑（含真浏览器 + 长跑局）
python run_all.py --quick    # 日常回归：跳过真浏览器脚本 + t_mock30
python run_all.py --fast     # 冒烟：只跑纯本地、秒级的（几十秒出结果）
python run_all.py t_rules    # 只跑名字里含这段的
python run_all.py --timeout 600   # 单个脚本超时改成 600 秒（默认 300）
```

2026-10-31 实测：`--fast` **87/87**（47.6 秒）、`--quick` **105/105**（139.9 秒）、
全量 **125/125**（2026-10-31 新增 `t_settings_midgame.py`；上一轮 145.8 秒零跳过，本轮未重跑全量）。

- **三档不是层层收窄**：`--fast` 不带"纯本地但每个要几十秒"的那批（它们自己在等超时/退避/收尾窗口），
  `--quick` 才带；`--quick` 不带真浏览器，也不带 `t_mock30.py` 这局长跑局。
  每档跑完都会打印"跑了 N 项 / 跳过了谁 / 按什么判据跳的"。
- **三档的判据**都在 `run_all.py` 顶部的分档清单里，一组一个 `#` 注释说明依据（不靠探测猜）。
  **新加了测试要顺手登记**：忘了登记不会静默漏跑 —— 全量照跑，`--fast/--quick` 会把它列进
  "未分类"并在开头大声点名。
- **共享的东西由 runner 起一次**：测试实例（**8086 / 8088 / 8089 三台**，探活轮询就绪，不固定 sleep；
  各自一份 save_dir，见 `run_all.py` 的 `TEST_INSTANCES`）、本地假上游 8098（测试实例的模型都打它，
  所以**回归不会花你的钱**）、线上 8077 只探活不启动（要页面/存档接口测试就自己先起）。
  三台实例若已在跑则**复用、跑完不动它**；跑完汇总里会打印假上游的请求计数（花钱审计）。
  ⚠️ 跑在非 8086 实例上的脚本必须写 `PORT = int(os.environ.get("WW_TEST_PORT") or 8086)`，
  否则它会**悄悄跑回 8086**，和那条链上的脚本抢同一个房间（runner 会在开头点名这种脚本）。
- **为什么服务端要拆成三台**：服务端是**单房间**的（一台实例同一时刻只能跑一局），
  而最慢的四个脚本（`t_adversarial` 101s / `t_cancel_paths` 84s / `t_frontend_gaps` 55s /
  `t_http` 34s）原来全挤在 8086 上串行 = 287 秒。拆开车道之后全量 310 → **145.8 秒**。
  有三类脚本**必须留在 8086**：它们直接读/写 `tests/tmp/games`（`t_isolation_push` / `t_ws_e2e`
  读"最新那一局"，`t_frontend_gaps` 往里写一份假存档）。
- **失败**：单个脚本超时（默认 300 秒）即判失败，并**连它拉起的子进程树一起清理**
  （有的脚本自己会起假上游 / 测试服务 / 子进程，只杀直接子进程会留下孤儿占端口）。
  失败脚本的日志路径会打印成可直接复制的绝对路径。
